# 展示数据性能验证（2026-10-16）

发布事务准备最终展示数据；Reports、Articles、Dates、报告右侧文章、详情和分页读取持久展示表。原入库、审核、可见性和下载校验保留。此记录是实现及隔离验证，生产尚未部署或迁移。

## 原来的慢在哪里

原接口在每次点击时重新检查发布记录、拼接整份 PDF 报告的文章、解析分类和校验展示内容，最后才截取当前页。真实数据中，发布记录核对单次约 0.92 秒；最新 PDF 右侧只展示 5 篇，却先处理 83 个候选及约 590 次分类解析。Dates 分页前也会重复做内容哈希及快照构造。因此右侧文章比总列表更慢。

本次在原 SQLite 中增加展示表，由发布事务同步生成最终响应。GET 直接查询所需行；原入库和审核表继续保留。展示表更新与发布一起提交或回滚，没有新增第二套入库流程。

## 数据与返回内容

使用生产 SQLite 的一致备份（2,044,383,232 字节），覆盖 33 份公开报告、437 篇合并文章。升级至 schema 24 后，原业务表行数及公开 revision `4e74ffac0bec33785cc4d856a658f6bfefcdee8f090a5de5644da0766443d075` 均不变。

736 组业务响应逐项 SHA 对照，无差异。覆盖全部报告分页、文章详情及日期/来源/搜索等筛选；只排除不透明缓存版本，并将预期 schema 版本变化归一化。发布、撤回、回滚和禁止 GET 重建另有专项覆盖。

## 实测耗时

同一生产服务器、同一依赖镜像。旧版为未修改的服务容器内 HTTP 样本；新版为完整数据副本的隔离容器 HTTP，每个接口 5 次，表中取中位数。隔离容器只加载导航接口，未加载无关的聊天知识库。均排除公网和 TLS 延迟；这是开发版本的性能证据，不代表已经上线。

| Articles列表 | 1.254 秒 | 9.3 毫秒 |

新版全部采样接口首次请求最长 72 毫秒。经 SSH 隧道从本机读取时，各接口中位数约 0.05–0.10 秒。浏览器已验证四份 PDF 报告切换、右侧翻页、文章详情、Articles 翻页及 Dates 翻页；控制台无警告或错误。

完整展示补建本机约 45.1 秒、峰值 RSS 499.8 MiB。服务器展示接口隔离容器实测约 97.2 MiB（不含聊天知识库，不能作为完整应用内存对照）。初次上线需要通过现有 `migrate-publication` 明确迁移及补建；GET 不执行这项工作。

发布并发也用完整真实副本验证：写入尚未提交时，独立连接读取旧展示版本约 6.1 毫秒，没有出现数据库锁定。专项测试覆盖已有/新事务、提交/回滚/异常及不同缓存设置共 12 组。更新过程中临时抑制 SQLite 缓存溢写，避免写事务提前取得排他锁；提交后读者才看到新版本。参见 [SQLite cache_spill 文档](https://sqlite.org/pragma.html#pragma_cache_spill)。

服务器测速后只有写入侧并发保护与提交顺序调整；最终 API、展示 Reader 和其余读取依赖均与测速版本相同，已做源码/AST 核对。最终代码另外重跑了全部 736 组业务响应对照。
